# تنفيذ Responsive — الدفعة الأولى

تاريخ التحقق: 6 أكتوبر 2026.

تحديث لاحق: تم تنفيذ جولة عمليات الحفظ والفشل؛ التفاصيل في [تقرير الخطوة الثانية](responsive-step2-operations.md). الأرقام أدناه تخص الدفعة الأولى.

تم تنفيذ أساس الـ responsive عبر الموديولات الأساسية، مع الحفاظ على البيانات وسلوك العمليات. هذه الدفعة لا تغلق جميع شروط القبول في [الخطة](responsive-rollout-plan.md)؛ التغطية التالية تحدد ما تم التحقق منه فعليًا وما يحتاج جولة لاحقة.

## التغييرات المنفذة

- **المكونات المشتركة:** إعادة تنظيم SideDrawer ليلائم عرض الشاشة واتجاه اللغة، مع منطقة محتوى قابلة للتمرير وارتفاع `100dvh` وزر إغلاق 44px. إضافة قفل تمرير يدعم فتح أكثر من overlay ويحفظ الحالة الأصلية، مع اختبارات لاسترجاعها. نماذج directory-workspace تتكيف مع عرض الـ drawer الفعلي. تحسين موضع Toast ومقاس زر الإغلاق.
- **بوابة الطبيب:** تحويل تخطيطات العيادات والمواعيد والتشغيل والفترات والملف الشخصي والاستقبال والانضمام إلى Container Queries، ومعالجة الحدود الدنيا التي كانت تمنع الأعمدة من الانكماش. نموذج إنشاء العيادة وصلاحيات موظف الاستقبال يعملان داخل drawer ضيق حتى على desktop. صفحة الانضمام تستخدم PageHeader المشترك.
- **العمليات والموديولات الطبية:** تكييف تخطيط الكشف والمتابعات والتذاكر، وحذف قواعد `!important` من حوارات المالية وقائمة الانتظار. التحقق من دليل الأدوية وطلبات الإضافة والروشتات والاستيراد على الأحجام الثمانية، بما يشمل الحوارات والنماذج والبحث.
- **بوابة المريض والاكتشاف:** تكييف الملف والعائلة ودليل الأطباء وتفاصيل الطبيب والمساحات الرئيسية حسب الحاوية، مع فحص أسماء ونصوص طويلة بالعربي والإنجليزي.
- **التسجيل:** استخراج CSS المشترك بين تسجيل الطبيب والمريض بدل نسختين متطابقتين، وتبسيط الشبكة وأقسام الفورم وتوحيد select والتبديل الخاص بإظهار كلمة المرور.
- **الصفحات القانونية:** استخراج أنماط التنقل المتكررة داخل feature القانونية، وإصلاح قصّ التبويبات على الموبايل. اختبار حدود كل تبويب صراحةً.
- **التنظيف والترجمة:** حذف الزخارف والـ wrappers والقواعد القديمة التي استُبدلت. إزالة 109 قواعد و25,124 بايت من مجموعة الـ16 ملف CSS المقاسة، قبل احتساب تقليل تكرار التسجيل والتنقل القانوني. ترجمة النصوص الثابتة المتأثرة في محرر العيادة والتشغيل والجدول وتفاصيل الطبيب، واستكمال المفاتيح الناقصة.

الأنماط المشتركة الخاصة بالتسجيل والقانونية تبقى داخل feature الخاصة بها؛ لم يُنقل منطق أعمال إلى Shared ولم تتغير عقود الـAPI ضمن هذه الدفعة.

## ملاحظات لم تُغلق

1. فحصا Architecture وi18n على مستوى المشروع لا ينجحان بسبب مخالفات سابقة، منها imports داخلية بين features، منطق أعمال في Shared، و`!important` في CSS عام ونصوص عربية قديمة. السجلات: `.tmp/responsive-final-architecture.log` و`.tmp/responsive-final-i18n.log`. لا يُعتبر نجاح build بديلًا لنجاحهما.
2. CSS صفحة دليل الأطباء حجمه **37.02kB** مقابل budget **35kB**؛ التحذير موجود من قبل، وقد انخفض الحجم في هذه الدفعة.
3. اختبار Admin reservations الأساسي يفشل في تحميل المسار: بيانات المسار تتطلب actor `Admin` بينما fixture تستخدم `SuperAdmin`، والـ guard يقارن userType حرفيًا. لم نغيّر الصلاحيات لمعالجة اختبار responsive؛ تمت إعادة تشغيل doctors وsuperadmins منفصلين بنجاح. حجوزات الطبيب والمريض ضمن المصفوفة الناجحة.
4. ما زالت بوابة اعتماد كل موديول تحتاج فحص جميع حالات validation/loading/pending وتفاعل الحفظ والفشل وtoast، وOTP/reset-password، والتفاصيل الفرعية غير الموجودة في مصفوفة المسارات. لا تعني التغطية العامة اعتماد كل workflow.
5. سلوك لوحة المفاتيح الفعلية على هاتف، landscape والارتفاعات الصغيرة يحتاج تحققًا إضافيًا. الفحص الحالي محاكاة Chromium بارتفاع 900px، مع مراجعة صور مختارة على 390/820/1440.

## الخطوة التالية في الخطة

استكمال مصفوفة الحالات والتفاعلات لكل capability، بدايةً بحفظ العيادات وجداولها وإدارة الاستقبال، ثم الحجز والمالية، ثم auth verification/reset. بعدها يمكن اعتماد الموديولات منفردة وفق شروط الخطة، دون افتراض اكتمالها من فحص العرض فقط.

## إعادة التشغيل

بعد تشغيل التطبيق على المنفذ 4201 ومتصفح CDP على 9244:

```powershell
$env:WASLA_ORIGIN = 'http://127.0.0.1:4201'
node scripts/browser-portal-responsive.cjs
$env:WASLA_WIDTHS = '320,390,600,768,820,1024,1280,1440'
$env:WASLA_OUTPUT = 'docs/browser-verification/responsive/clinical'
node scripts/browser-phase14.cjs
```

يمكن تخصيص `WASLA_ROUTES` بقائمة مسارات مفصولة بفواصل و`WASLA_STATE` إلى `empty` أو `error` في سكربت البوابات. شغّل جولات المتصفح بالتتابع لأن اللغة محفوظة في localStorage المشترك لنفس origin.
