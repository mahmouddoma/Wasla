# الخطوة الثانية — عمليات الحفظ والفشل

تاريخ التنفيذ: 6 أكتوبر 2026.

النطاق: الحفظ والتعديل والفشل والـ validation والـ toast في إدارة العيادات والجداول والمساعدين والحجوزات والمالية. استُخدمت استجابات API اصطناعية فقط.

## الإصلاحات

- **محرر العيادة:** إظهار toast عند فشل الحفظ أو فشل تحديث البيانات بعد تعارض، ومنع إرسال النموذج أثناء تحميل المواقع أو طلب جارٍ. الاحتفاظ بأحدث rowVersion من الاستجابة حتى تستخدمه إعادة المحاولة؛ كان النموذج يعتمد على النسخة القديمة من input قبل تحديث الأب.
- **جداول العيادة:** الاحتفاظ بقفل العملية حتى تنتهي إعادة تحميل الجدول والعرض الفعلي معًا. كانت استجابة العرض الفعلي تزيل activeAction قبل اكتمال الطلب الآخر. إضافة تحقق من صلاحية الإدارة داخل معالجات الحفظ والحذف.
- **صلاحيات المساعدين:** إضافة toast لأخطاء حفظ الصلاحيات وتفعيلها وتعطيلها، ومعالجة فشل تحديث التفاصيل بعد 404/409 داخل catch مستقل حتى لا يخرج خطأ غير معالج. تصحيح مفتاح رسالة فشل إنشاء المساعد إلى مفتاح مترجم موجود.
- **التشغيل والهوية:** التحقق من صلاحية الإدارة داخل معالجات التشغيل والإعدادات والهوية ورفع/حذف الشعار، إلى جانب إخفاء/تعطيل الإجراءات في الواجهة. حماية الخادم تظل المرجع للصلاحيات.
- **الشرائح والأسعار:** إظهار toast لأخطاء العمليات العادية، بما يشمل فشل حذف سعر؛ كانت التغذية الراجعة بالتوست محصورة في تعارض 409.

التعديلات داخل المكونات الحالية. لم تتغير عقود API أو إعدادات الصلاحيات أو منطق حسابات الدفع.

## الاختبارات السلوكية المضافة

| الجزء | التغطية الجديدة |
| --- | --- |
| محرر العيادة | نموذج غير صالح، منع الإرسال المكرر، زر حفظ معطّل أثناء الطلب، emit وtoast عند النجاح، الحفاظ على المدخلات عند الفشل، rowVersion حديث عند إعادة المحاولة |
| الجدول | استمرار القفل طوال إعادة التحميل، منع عملية على عرض للقراءة فقط |
| إعدادات التشغيل | منع الحفظ المكرر، تحديث النسخة بعد النجاح، رفض إعداد غير صالح، الحفاظ على المدخلات بعد الفشل، منع الحفظ دون صلاحية الإدارة |
| المساعدون | الحفاظ على الصلاحيات المختارة بعد الفشل، toast، منع طلب مكرر، معالجة فشل تحديث التفاصيل بعد تعارض التفعيل |
| الشرائح والأسعار | toast عند فشل حذف سعر مع الحفاظ على القائمة وإتاحة الإجراءات من جديد |
| الحجوزات | منع إلغاء مكرر، toast النجاح، بقاء المحرر والتفاصيل بعد فشل الإلغاء؛ اختبارات retry/idempotency/concurrency السابقة ما زالت ضمن المجموعة |
| المالية | validation لسبب الاسترداد، قفل العملية حتى ينتهي التحديث، toast النجاح والفشل، وتصحيح دفع عبر معالج الحفظ الفعلي مع الحفاظ على السبب بعد الفشل وإعادة المحاولة وتحديث rowVersion |

تم ضبط تنظيف لغة اختبارات العيادات والمساعدين لمنع تسريب الإنجليزية إلى اختبارات أخرى تعتمد على اللغة الافتراضية.

## فحص المتصفح

المجموعة الكاملة: **680 اختبارًا ناجحًا في 118 ملفًا** (18 اختبارًا إضافيًا). Production build ناجح، مع تحذير حجم CSS دليل الأطباء القائم. `git diff --check` ناجح. فحص الترجمة العام ما زال يفشل بمخالفات سابقة، ولا يسجل مخالفات في المكونات التي تغير سلوكها في هذه الخطوة.

- **16 سيناريو حفظ جدول:** العربية والإنجليزية × الأحجام الثمانية. كل سيناريو يرفض مدة غير صالحة دون API، ثم يحاكي فشل الحفظ ويختبر toast وبقاء النموذج ومنع تكرار الطلب، ثم يعيد الحفظ بنجاح ويختبر toast وإغلاق النموذج وتحديث القائمة.
- الملف `docs/browser-verification/responsive/step2-schedule/results.json` يحتوي 32 سجلًا: 16 سجل عرض و16 سجل تفاعل، دون سيناريو فاشل أو runtime errors.
- **160 فحص regression** للعيادات والتشغيل والشرائح والمساعدين والحجوزات والمالية بالعربي والإنجليزي على الأحجام الثمانية، بما يشمل حدود حقول create drawers والإغلاق واسترجاع التمرير.
- النتائج في `docs/browser-verification/responsive/step2-regression/results.json`. الصور والنتائج محلية حسب إعدادات Git الحالية.

لإعادة سيناريو الجدول، بعد تشغيل التطبيق ومتصفح CDP:

```powershell
$env:WASLA_ORIGIN = 'http://127.0.0.1:4201'
$env:WASLA_ROUTES = 'doctor/practices/p1#schedule'
$env:WASLA_MUTATIONS = 'schedule'
$env:WASLA_OUTPUT = 'docs/browser-verification/responsive/step2-schedule'
node scripts/browser-portal-responsive.cjs
```

يجب إزالة `WASLA_MUTATIONS` قبل جولات العرض العامة. جميع طلبات `/api/` في السكربت يعترضها CDP ويرد ببيانات اصطناعية؛ لا تصل mutations إلى الخادم الحقيقي.

## حدود الاعتماد

هذه الجولة تغطي العمليات والحالات المحددة أعلاه، ولا تعتمد جميع mutations في المشروع. ما زال مطلوبًا توسيع تفاعلات المتصفح لكل من الحجز الجديد والتأجيل وcheck-in وعمليات الاسترداد والشعار والاستثناءات والتفاصيل الفرعية، وفحصها على هاتف فعلي. نجاح فحص عرض صفحة مالية لا يثبت تنفيذ استرداد داخل المتصفح.

سجلات المجموعة الكاملة والبناء: `.tmp/responsive-step2-tests.log` و`.tmp/responsive-step2-build.log`. مخالفات Architecture والترجمة القديمة وتحذير حجم CSS دليل الأطباء موثقة في [تقرير الدفعة الأولى](responsive-rollout-progress.md).
